# v2 업적 시스템 — 설계 문서 (구현 금지)

> 이 문서는 설계 기록입니다. v1에는 어떤 업적 기능도 구현하지 않습니다.
> v1은 아래 "v1 선행 요구사항" 절의 세 가지만 만족합니다.

## 의도

디깅이라는 행위를 게임화한다: 디스코그래피 완주, 꾸준한 청취, 장르/연대를
가로지르는 폭넓음을 보상한다.

이 앱의 사용자는 정확히 한 명이므로 "전체 사용자 중 x%가 달성" 같은
희소성/달성률 지표는 무의미하며 **절대 포함하지 않는다**. 유의미한 대응물은
**개인 희소성**이다: 사용자 자신의 기록 중 조건을 만족하는 비율
(예: "5점을 준 트랙은 전체의 2%").

## 티어

브론즈 / 실버 / 골드 / 플래티넘. 플래티넘은 메타 업적 전용.

## 조건 타입 (로컬 데이터만으로 평가)

| 타입 | 설명 | 예시 |
| --- | --- | --- |
| `count` | 특정 종류의 이벤트 n회 | 아티스트 10명 완주 |
| `cumulative` | 합산 수치가 임계값을 넘음 | 총 청취 시간 100시간 |
| `single` | 조건을 만족하는 객체 1개 존재 | 트랙 50곡 이상인 앨범 완주 |
| `streak` | n일/주 연속으로 청취 이벤트 ≥ 1 | 30일 연속 청취 |
| `breadth` | 한 차원에서 서로 다른 값 n개 | 장르 10종, 발매 연대 5개, 아티스트 국적 |
| `composite` | 위 조건들의 AND/OR 조합 | — |
| `meta` | 티어 X 업적 n개 달성, 또는 특정 업적 세트 클리어 | 골드 5개 → 플래티넘 |

## 평가 모델

순수 함수 하나로 평가한다:

```ts
evaluate(achievement, snapshot) -> { earned: boolean; progress: number; target: number }
```

- `snapshot`은 모든 로컬 테이블(artists, albums, tracks, listenEvents,
  earnedAchievements)의 스냅샷.
- 상태를 바꿀 수 있는 모든 변이에서 실행: 트랙 상태 변경, 평점, 동기화
  가져오기, 범위/제외 변경, 백업 가져오기.
- 새로 달성된 업적은 기존 완료 토스트 컴포넌트(글래스 토스트)를 재사용해
  큐에 넣는다.
- progress는 반드시 실제 계산값이어야 하며 하드코딩 금지.

v1의 `src/utils/derive.ts`가 이미 노출하는 순수 함수들이 평가의 기반이 된다:
`countCompletedArtists`, `totalListenEvents`, `distinctGenres`,
`listenStreak` 등.

## 저장

Dexie 테이블 2개를 **새 스키마 버전으로** 추가한다 (기존
`.version(1)` 체인 아래에 `.version(2).stores({...})` 를 덧붙이는 방식 —
비파괴 업그레이드):

- `achievements` — 업적 정의. 정적 파일에서 시드하고, 이후 사용자 확장 가능.
- `earnedAchievements` — `{ achievementId, earnedAt, snapshotNote }`.

달성 기록은 JSON 내보내기/가져오기에 반드시 포함한다
(`src/db/backup.ts`의 스키마 버전을 올리고 두 테이블을 직렬화).

## UI

- `/profile`에 `업적` 탭 추가 (기존 탭과 같은 `?tab=` URL 쿼리 방식).
- `ProfileHeader`를 쇼케이스 스트립으로 확장: 최근 달성 + 고정(핀) 즐겨찾기.
  v1에서 이미 prop 기반 독립 컴포넌트로 분리되어 있으므로 props만 추가하면 된다.
- 미달성 업적은 진행률 바를 보여준다.
- 히든 업적은 달성 전까지 실루엣과 티어만 보여준다.

## v1 선행 요구사항 (이것만 v1 범위)

1. **Dexie 스키마 버전 체인** — `src/db/dexie.ts`는 명시적
   `.version(1).stores(...)` 체인으로 작성되어 있어 테이블 추가가
   비파괴적이다. ✅
2. **독립 컴포넌트** — `ProfileHeader`와 완료 토스트는 prop 기반 독립
   컴포넌트로, 페이지 로컬 결합이 없다. ✅
3. **파생 지표의 순수 함수화** — 업적에 필요한 모든 파생 지표(완주
   아티스트 수, 총 청취 이벤트, 고유 장르, 청취 스트릭)는 `/profile` 통계
   JSX 안이 아니라 `src/utils/derive.ts`의 순수 함수로 노출된다. ✅
